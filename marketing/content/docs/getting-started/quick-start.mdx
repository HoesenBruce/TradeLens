> **Current TradeLens status:** official TradeLens images are not yet published. Docker image publishing and Release Please are disabled. Use `make up-build` (SQLite) or `make up-postgres-build` (PostgreSQL) to build this checkout.
>
> **Database boundary:** `make up` and `make up-postgres` currently pull upstream TraderMemos images (`sinhong2011/tradermemos-*`) by default. Upstream and TradeLens migration histories have diverged. Never alternate them against the same existing database volume, including PostgreSQL. Use a separate Compose project and fresh database/volumes for a different product; retain a complete backup before any migration.

Build the TradeLens Web UI and API from this checkout:

```bash
git clone https://github.com/HoesenBruce/TradeLens.git
cd TradeLens
make up-build    # http://localhost:3000
```

That's it. Same-origin `/api` — no CORS, leave the **Server** field blank. On first visit the
**setup wizard** creates your owner account — then head to
[First steps](/en/docs/getting-started/first-steps).

## Options and production notes

```bash
cp .env.example .env
make up-build           # SQLite
# OR, on a separate new installation:
make up-postgres-build  # PostgreSQL
```

For production, set `TM_JWT_SECRET=$(openssl rand -hex 32)` and put TLS in front — see
[Deploy](/en/docs/self-hosting/deploy) and
[Reverse proxy](/en/docs/self-hosting/reverse-proxy). All server settings are in the
[Configuration reference](/en/docs/self-hosting/configuration).

## Local development

```bash
git clone https://github.com/HoesenBruce/TradeLens.git
cd TradeLens
make setup && make dev   # API :8080 + web :5173
```

See [CONTRIBUTING.md](https://github.com/sinhong2011/TraderMemos/blob/main/CONTRIBUTING.md) for
targets, Vite+ commands, and project structure.

### Demo data

Fill any instance with ~200 generated trades over the last three months:

```bash
make demo-seed API=http://localhost:3000/api/v1 EMAIL=you@example.com PASSWORD='…'
```

It talks to the public API only, so it works against a local stack or a deployed demo.
Re-running is a no-op — fills are deduplicated server-side.
