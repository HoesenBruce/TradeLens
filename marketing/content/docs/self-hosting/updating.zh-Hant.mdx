> **TradeLens 目前狀態：** `make up` / `make up-postgres` 預設使用官方 `ghcr.io/hoesenbruce/tradelens-*` 映像；原始碼建置可用 `make up-build` / `make up-postgres-build`。自動發布仍被停用。
>
> **資料庫邊界：** 上游 TraderMemos 與 TradeLens 的遷移歷史已分岔，不可共用既有資料庫或資料卷（包括 PostgreSQL）。切換產品應使用獨立專案與全新資料庫；任何部署變更前保留完整備份。

每次升級前都備份完整實例。API 啟動時自動執行遷移，不支援自動降級；回滾時使用匹配的原始碼版本恢復升級前的資料庫與附件。 [→ 備份與恢復](/zh-Hant/docs/self-hosting/backup-restore)

## 原始碼更新（目前 TradeLens 路徑）

保留既有目錄、Compose 專案名、`.env` 與資料卷，更新前檢查目標版本及變更。依現有實例選 SQLite 或 PostgreSQL 命令，不要對同一資料庫輪流執行兩種設定。

```bash
git pull --ff-only
make up-build           # SQLite
# OR: existing PostgreSQL installation
make up-postgres-build
```

用 `curl -fsS http://localhost:3000/healthz` 核對執行版本。可重複建置應記錄 Git commit；`TM_IMAGE_TAG` 只標記本地鏡像，不會選擇原始碼版本。

## 預建鏡像（上游或自有發佈者）

僅適用於沿用同一發佈者、同一遷移鏈的既有鏡像部署：在 `.env` 用 `TM_IMAGE_TAG` 鎖定實際可用標籤，拉取後用原有 Compose 設定重啟。目前不承諾官方 TradeLens 標籤或多架構鏡像。不要在 TradeLens 原始碼實例上走此路徑。

## CDN／託管 API

從選定的 TradeLens 版本更新。自動部署取決於服務商設定；本 fork 的 Vercel 發佈工作流程目前停用。保留 API 資料庫與附件卷。同步上游程式碼不能替代遷移相容性審查。
