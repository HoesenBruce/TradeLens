> **TradeLens 当前状态：** 官方 TradeLens 镜像尚未发布；Docker 镜像发布与 Release Please 均已禁用。请用 `make up-build`（SQLite）或 `make up-postgres-build`（PostgreSQL）从当前源码构建。
>
> **数据库边界：**`make up` 与 `make up-postgres` 目前默认拉取上游 TraderMemos 镜像（`sinhong2011/tradermemos-*`）。上游与 TradeLens 的迁移历史已分叉，切勿交替连接同一个已有数据库卷，包括 PostgreSQL。尝试另一产品时使用独立 Compose 项目及全新数据库／数据卷；任何迁移前保留完整备份。

每次升级前都备份完整实例。API 启动时自动执行迁移，不支持自动降级；回滚时使用匹配的源码版本恢复升级前的数据库与附件。 [→ 备份与恢复](/zh-Hans/docs/self-hosting/backup-restore)

## 源码更新（当前 TradeLens 路径）

保留已有目录、Compose 项目名、`.env` 与数据卷，更新前检查目标版本及变更。根据现有实例选 SQLite 或 PostgreSQL 命令，不要对同一数据库轮流执行两种配置。

```bash
git pull --ff-only
make up-build           # SQLite
# OR: existing PostgreSQL installation
make up-postgres-build
```

用 `curl -fsS http://localhost:3000/healthz` 核对运行版本。可重复源码构建应记录 Git commit；`TM_IMAGE_TAG` 只标记本地镜像，不会选择源码版本。

## 预构建镜像（上游或自有发布者）

仅适用于沿用同一发布者、同一迁移链的已有镜像部署：在 `.env` 用 `TM_IMAGE_TAG` 锁定实际可用标签，拉取后用原有 Compose 配置重启。当前不承诺官方 TradeLens 标签或多架构镜像。不要在 TradeLens 源码实例上走此路径。

## CDN／托管 API

从选定的 TradeLens 版本更新。自动部署取决于服务商配置；本 fork 的 Vercel 发布工作流目前禁用。保留 API 数据库与附件卷。同步上游代码不能替代迁移兼容性审查。
