title: Updating
description: Update official TradeLens images or source builds while preserving data.
---

> **Current TradeLens status:** official TradeLens GHCR images are published. `make up` (SQLite) and `make up-postgres` (PostgreSQL) use them by default. Source-build fallback remains available through `make up-build` / `make up-postgres-build`. Docker publisher and Release Please remain `disabled_manually`; image availability does not imply continuous publishing is enabled.
>
> **Database boundary:** TradeLens and upstream TraderMemos migration histories have diverged. Never hand a database used by one product to the other, including PostgreSQL. Use separate projects and fresh databases for different products. Switching an existing TradeLens source deployment to official TradeLens images is a same-product deployment change: take a complete backup, then preserve the checkout, Compose project, configuration and volumes.

Back up the complete instance before every upgrade. Migrations run automatically on API startup; there is no automatic downgrade. Restore the pre-upgrade database and attachments with the matching image version or source revision for rollback. [→ Backup & restore](/en/docs/self-hosting/backup-restore)

## Official image updates

Keep the checkout, Compose project name, `.env` and volumes. Back up the complete
instance first. Review the target release, then update the checkout:

```bash
git pull --ff-only
# Edit .env: change TM_IMAGE_TAG=0.2.1 to the next published stable version.
# For example, use 0.2.2 only once that release actually exists.
docker compose pull
docker compose up -d
```

For PostgreSQL, use `docker compose -f docker-compose.yml -f docker-compose.postgres.yml`
for both commands. Never run `down -v`: retain the database and attachments volumes.
Migrations run automatically at API startup. Verify `/healthz`, login and data.
If migrations changed the database, switching back to an old image alone is not a
safe rollback: restore the pre-upgrade backup with its matching image version.

`latest` is a moving stable tag; production should pin a stable semver. Digest
references in a Compose override can pin exact API/Web content for audit/rollback.

## Source fallback and switching to official images

```bash
git pull --ff-only
make up-build           # SQLite
# OR: existing PostgreSQL installation
make up-postgres-build
```

Source builds use the current checkout; record its Git SHA. `TM_IMAGE_TAG` supplies
metadata and does not select source. To switch an existing **TradeLens** source
installation to official images, take a full backup, keep the same checkout/project,
`.env` and volumes, select a compatible stable image version, then use the official
pull/up commands above. This is a same-product deployment change, not permission
to reuse an upstream TraderMemos database.

## CDN / hosted API

Update from your chosen TradeLens revision. Deployment automation depends on your provider configuration; the fork’s Vercel release workflow is currently disabled. Preserve the API database and attachments volume. Syncing upstream code is not a substitute for reviewing migration compatibility.
