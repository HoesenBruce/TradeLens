> **TradeLens の現在の状態：** `make up` / `make up-postgres` は公式 `ghcr.io/hoesenbruce/tradelens-*` イメージを使用します。ソースビルドは `make up-build` / `make up-postgres-build` です。自動公開は無効のままです。
>
> **データベースの境界：** 上流 TraderMemos と TradeLens のマイグレーション履歴は分岐しています。既存のデータベースやボリュームを共用しないでください（PostgreSQL も同様）。製品を切り替える場合は別プロジェクトと新規データベースを使い、配置変更前に完全なバックアップを保存してください。

更新前に毎回インスタンス全体をバックアップしてください。API 起動時にマイグレーションが自動適用されます。自動ダウングレードはありません。ロールバックには更新前のデータベースと添付ファイル、対応するソースリビジョンを使います。 [→ バックアップと復元](/ja/docs/self-hosting/backup-restore)

## ソース更新（現在の TradeLens の方法）

既存のディレクトリ、Compose プロジェクト名、`.env`、ボリュームを維持し、更新先と変更点を確認します。現在の構成に合わせて SQLite または PostgreSQL のコマンドを選び、同じデータベースに両構成を交互に使わないでください。

```bash
git pull --ff-only
make up-build           # SQLite
# OR: existing PostgreSQL installation
make up-postgres-build
```

`curl -fsS http://localhost:3000/healthz` で実行中のバージョンを確認します。再現可能なビルドのため Git commit を記録してください。`TM_IMAGE_TAG` はローカルイメージのラベルで、ソースリビジョンを選択しません。

## ビルド済みイメージ（上流または自分の公開元）

同じ公開元とマイグレーション履歴を継続する既存イメージ構成だけが対象です。`.env` の `TM_IMAGE_TAG` に実在するタグを指定し、取得後に元の Compose ファイルで再起動します。公式 TradeLens タグやマルチアーキテクチャイメージはまだ提供されていません。TradeLens のソース構成でこの方法を使わないでください。

## CDN／ホスト API

選択した TradeLens リビジョンから更新します。自動デプロイはプロバイダー設定に依存します。この fork の Vercel 公開ワークフローは現在無効です。API のデータベースと添付ファイルボリュームを維持してください。上流の同期だけではマイグレーション互換性の確認になりません。
